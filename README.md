# 识稼日报 · 作物病害识别与 3D 图谱

一个跑在自己电脑上的农作物病害诊断小站：拍一张叶片照片，出一张「病情诊断单」，旁边立起这个病的 3D 模型，能拖着转着看。

面向的是不会用专业 App 的种植户——所以整站只有一个大按钮、大字、大白话，没有登录、没有会员、不联网上报数据。

> 本项目为首届大学生人工智能素养大赛 A 赛道（智农助手）参赛作品。

---

## 它做什么

| 模块 | 说明 |
|---|---|
| **拍照识病** | 上传叶片照片，输出结构化诊断单：作物、病名、把握度、判断依据、严重度、生育期、防治窗口、用药处方、田间提醒，另附 2–3 个疑似候选 |
| **3D 病征模型** | 识别出病种后，自动立起对应的三维叶片／茎秆模型，鼠标拖动旋转、滚轮缩放，能直观看到「这个病长什么样」 |
| **农事问答** | 底部输入框，用大白话问种植问题，DeepSeek 作答 |
| **天气提示** | 自动拉取当地天气，喷药、灌水前先看一眼 |

支持 **18 种**常见病害，覆盖小麦、玉米、番茄、黄瓜、水稻五个作物（明细见下表）。

---

## 技术栈

- **后端**：FastAPI + Uvicorn，单文件 `main.py`
- **前端**：单文件 `index.html`，无框架、无构建步骤
- **3D**：three.js r147 + GLTFLoader，全部本地化（`lib/`），不依赖任何 CDN，断网也能看
- **识图**：阿里云百炼 DashScope 上的 **Qwen3-VL-Plus**（OpenAI 兼容模式）
- **问答**：DeepSeek Chat
- **模型**：Meshy 图生 3D 生成，导出 GLB

### 识别为什么准：两步走，而不是一次问完

一开始我们让模型一次填完整张 15 项诊断单，结果同一个病连跑三次能给出三种答案——同一张玉米大斑病的图，5 次里 2 次判成大斑、3 次判成小斑。

后来做了个对照实验：单独问它「病斑是长梭形还是椭圆形，只回答形状」，它答对了。

**问题不在模型看不见，而在一次塞太多任务会稀释它的注意力**——诊断单里一写上病名，模型就先押一个答案，后面所有描述都往那个答案凑。

所以改成两段：

1. **先只观察，不许提病名**。只记 9 项客观特征：作物、部位、形状、斑长占叶宽几分之几、斑数、中央色、边缘色、表面特征、分布方式。
2. **再判断**。把这份观察记录当纯文字交给模型，对照鉴别表开诊断单。这一步是文本推理，不再有「看着图猜」的空间。

改完在同一套 18 张样图上连测三轮：**100% / 94% / 100%**；玉米大斑连跑 3 次全对，番茄晚疫从「5 次全错」变成稳定判对。

代价是响应从约 5 秒变成 6.5–7.5 秒。

## 快速开始

需要 Python 3.10+。

```bash
git clone https://github.com/planet1227/crop-disease-3d.git
cd crop-disease-3d

pip install -r requirements.txt

# 配密钥
copy .env.example .env          # macOS/Linux 用 cp
# 打开 .env，把两个 key 换成自己的

python start.py                 # 或 python main.py
```

浏览器打开 <http://127.0.0.1/>。

**手机访问**：电脑和手机连同一个 WiFi，用 `ipconfig` 查电脑的局域网 IPv4，手机浏览器输 `http://<那个IP>` 即可。

### 两个密钥去哪儿申请

| 变量 | 用途 | 地址 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 农事问答 `/chat` | <https://platform.deepseek.com/api_keys> |
| `DASHSCOPE_API_KEY` | 视觉识别 `/vision` | <https://bailian.console.aliyun.com/> |

`.env` 已在 `.gitignore` 里，不会被提交。**别把密钥硬编码回 `main.py`**。

## 关于 3D 模型（重要）

**`models/*.glb` 不在本仓库里。** 18 个模型合计约 435 MB（单个最大 61 MB），塞进 Git 会让 clone 变得非常慢。仓库里保留的是 `models/参考图/` 下的 **18 张病害样图**，你可以拿它们自己去生成模型。

想补上模型，两条路：

1. 用 [Meshy](https://www.meshy.ai/) 的图生 3D，上传 `models/参考图/` 里对应那张图，导出 GLB 后命名为 `<作物><病名>.glb` 放进 `models/`；
2. 自己另找素材或用别的建模工具，只要文件名对齐 `lib/disease3d.js` 里 `DISEASES` 的 key 就行。

模型目录约定：

```
models/
├── 小麦条锈病.glb
├── 小麦叶锈病.glb
├── ...（共 18 个）
└── 参考图/
    ├── 小麦条锈病_参考图.png
    └── ...
```

**缺模型时页面不会崩**，只是 3D 那一栏显示空白，识别、诊断单、问答照常工作。

## 识别准确率说明

上面那个 100% 是在**本项目自建的 18 张样图**上测的——每个病一张、构图干净、纯白背景。**真实田间照片会明显低于这个数字**：逆光、模糊、多病并发、叶面沾泥都会掉准确率。

所以诊断单里一直保留了「把握度」和「候选病种」两栏，**它的定位是给种植户一个参考方向，不能替代农技人员现场判断**。用药前请按当地植保站口径复核。

## 已知限制

- 只认这 18 种病，其他病害会往最像的那个猜
- 一次只认一张图，一张图里混了两种病时只报主要的那个
- 依赖外部 API，断网或额度用尽时识病不可用（3D 和页面本身不受影响）
- 大面积模型（稻曲病 61 MB、黄瓜霜霉病 56 MB）在低端手机上加载较慢
